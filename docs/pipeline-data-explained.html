🗺 Peta Besar: Dua Rangkaian Tahap

Pipeline terdiri dari dua rangkaian: Tahap A (korpus Mendeley — sudah selesai, hasilnya units.csv / documents.csv / texts/) dan Tahap B (build v4.1 Anda — mengubah korpus menjadi dataset siap-embed di dataset_ready/combined/result/). Contoh data di bawah semuanya asli.

🎯
Kisah contoh yang dipakai di seluruh halaman ini: satu ayat hukum nyata — Pasal 18 Ayat (1) UUD 1945 Perubahan Kedua — diikuti langkah demi langkah: bagaimana ayat itu keluar dari PDF, masuk ke CSV, menjadi chunk, digabung ke parent, lolos QA, dan akhirnya siap dijadikan vektor untuk retrieval.

1 Akuisisi — Mengumpulkan PDF Resmi Tahap A

378 PDF peraturan diunduh dari portal JDIH pemerintah (peraturan.go.id, JDIH Bawaslu, dll.), disimpan sebagai file sumber immutabel dalam folder per jenis peraturan.

  struktur sumber (PDF tidak ikut didistribusikan — hanya direkam identitasnya)
data-source/
├── 01-UUD/          UUD 1945 Perubahan Kedua_2000.pdf   ← contoh kita
├── 02-TAPMPR/
├── 03-UU/           UU-NO-7-TAHUN_2017.pdf
├── 04-PERPPU/  05-PP/  06-PERPRES/  07-PERMEN/
└── 08-PERLEMBAGA/   Bawaslu_NOMOR  15 TAHUN_2012.pdf  (folder campuran: PerKPU, PerBawaslu, DKPP…)
⚠️
Jebakan yang diketahui: nama file sering salah. Audit penulis menemukan hanya ±19% nama file akurat. Contoh nyata dari scripts/audit_identitas.py: file PERLEMBAGA_Nomor_3_Tahun_2019.pdf ternyata isinya PKPU 9/2019. Karena itu identitas tidak boleh diambil dari nama file → lihat Tahap 5.

2 Ekstraksi Teks — PDF → Teks Per-Halaman pypdf texts/

Setiap PDF dikonversi menjadi satu file teks polos. Batas halaman eksplisit dengan penanda === PAGE n ===, dan setiap baris non-kosong punya nomor urut stabil dalam halamannya. Ini fondasi seluruh sistem provenance.

  texts/01-UUD/UUD 1945 Perubahan Kedua_2000.txt — potongan asli, halaman 1
=== PAGE 1 ===                    ← penanda halaman 1
PERUBAHAN KEDUA UNDANG-UNDANG DASAR NEGARA REPUBLIK INDONESIA   ← baris 1
TAHUN 1945 DENGAN RAHMAT TUHAN YANG MAHA ESA                 ← baris 2
MAJELIS PERMUSYAWARATAN RAKYAT REPUBLIK INDONESIA,           ← baris 3
Setelah mempelajari, menelaah, dan mempertimbangkan …        ← baris 4
…
(1) Negara Kesatuan Republik Indonesia dibagi atas daerah-daerah  ← baris 16 ★ AYAT KITA
provinsi dan daerah provinsi itu dibagi atas kabupaten dan kota,  ← baris 17
yang tiap-tiap provinsi, kabupaten, dan kota mempunyai pemerintah ← baris 18
daerah, yang diatur dengan undang-undang.

Alamat halaman 1, baris 16–18 inilah yang nanti direkam di units.csv dan diwarisi chunk — sehingga setiap potongan norma bisa diverifikasi balik ke teks aslinya (provenance contract).

5 Identitas & Klasifikasi Hukum documents.csv

Untuk tiap dokumen, jenis/nomor/tahun dibaca dari blok judul dokumen itu sendiri (dipotong di marker pertama: Menimbang / Mengingat / Memutuskan), lalu diklasifikasikan dua sumbu menurut UU 12/2011.

⚖️
Sumbu I — "I-ladder" (Pasal 7 ayat 1): tangga peraturan
UUD → TAP MPR → UU/PERPPU → PP → PERPRES
🪜

6 Audit Kualitas per Unit IndoBERT tokenizer

Setiap unit dinilai otomatis: panjang token & rasio [UNK] diukur dengan tokenizer IndoBERT, lalu diberi quality_flag (logika nyata dari corpus_service.py fungsi _quality_flag).

FlagKapanContoh nyata
ok≥4 token, ≥18 karakter, rasio [UNK] < 25%unit 400519 (44 token, 0.0) → ok
structural_headingSemua heading BAB/Paragraf/Pasal — label konteks, bukan norma"Pasal 18" → structural_heading
structural_adminSerpihan administratif: blok tanda tangan, header Lembaran Negara, "cukup jelas", nomor "12/34""WAKIL KETUA, Ttd." → structural_admin
needs_review_shortTerlalu pendek (<4 token / <18 char) — kandidat serpihanfragmen < 8 token → is_fragment
needs_review_oovRasio [UNK] ≥ 25% — teks kotor/simbol anehhasil OCR rusak → needs_review_oov

  "text": "(1) Negara Kesatuan Republik Indonesia dibagi atas daerah-daerah provinsi…\n\n(2) Pemerintah daerah provinsi…\n\n(3) … (7) Susunan dan tata cara penyelenggaraan pemerintahan daerah diatur dalam undang-undang.",  ← PASAL UTUH
  "window_ids": [ "uud-1945-perubahan-kedua-2000::p::18::w01" ]  ← 1 window (≤1.800 char)
}

Parent > 1.800 karakter dipecah window deterministik dengan overlap 150 char (window_id = {parent_id}::w{nn}) — 1.632 dari 11.413 parent mengalaminya. Pasal 18 (1.059 char) cukup satu window. Ini pola small-to-big: retrieval presisi di child (ayat), jawaban berkonteks pasal utuh.

7d. QA provenance otomatis — gate build

300 sampel chunk dipilih (seed tetap), isinya dicek balik ke halaman + rentang baris di texts/ (prefix 60 char): 294 terverifikasi / 300 = 98%, ambang minimal 90% → qa_gate: PASS. Contoh 6 kegagalan pun direkam di manifest, misalnya:

{ "chunk_id": "perlembaga-nomor-04-tahun-2011::p::4::35",
  "src": "2011, no.376 10 a) ruang kerja dengan luas 14 m²;",   ← file sumber
  "txt": "10 a) ruang kerja dengan luas 14 m²;",              ← isi chunk
  "note": "unverified = baris penanda struktural yang dipangkas builder; isi norma tetap utuh" }
