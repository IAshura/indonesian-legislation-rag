Bab 08 · Struktur Indeks

HNSW vs IVF vs FLAT: Cara Cepat (dan Jujur) Mencari Tetangga Terdekat

Bab ini meringkas pipeline/README-retrieval.md: tiga struktur pencarian vektor, apa saja yang berubah kalau berganti jenis (hanya dua titik!), tiga jebakan yang nyata dialami, dan kenapa “exact search numpy” dipakai sebagai kebenaran acuan.

⏱️ ±10 menit baca Sumber: README-retrieval.md · insert_milvus.py · eval_retrieval.py

1. Dua tempat pencarian di proyek ini

TempatJenis saat iniFile
Milvus (Docker lokal)HNSW + metrik IP, search ef: 64insert_milvus.py · smoke_milvus.py
Eval (numpy murni)Brute force / exact — emb @ q ke seluruh vektoreval/eval_retrieval.py baris 110 · cell 7 Colab
Artinya: baseline exact search sudah ada dan selalu bisa jadi “jawaban benar” pembanding. HNSW/IVF baru dianggap layak bila hasilnya mendekati baseline ini dengan latensi lebih murah.

2. Tiga jenis pencarian — konsep singkat

JenisCara kerja (analogi pemula)RecallKecepatan di data kita
FLAT (exact)Query dibandingkan ke semua vektor satu per satu, ambil top-k — seperti membaca seluruh kamus demi satu kata. Kebenaran mutlak.100%~10–50 ms (63 rb × 1024 — masih sangat cepat)
HNSWMembangun graph tetangga-terdekat berlapis; pencarian greedy dari titik masuk — seperti bertanya dari satu kenalan ke kenalan yang lebih dekat tujuan, lapis demi lapis.~99–100% bila ef cukup~1–5 ms
IVF (IVF_FLAT)Ruang vektor dibagi jadi nlist kluster (centroid k-means); query hanya mengecek nprobe kluster terdekat — seperti mencari buku hanya di rak-rak yang paling relevan.Bergantung rasio nprobe/nlist~2–10 ms

Metrik IP dipakai semua jenis karena vektor kita sudah L2-normal — dot = cosine. Ini tidak berubah kapan pun index diganti.

3. Yang berubah kalau berganti jenis: hanya dua titik

a) Saat membuat koleksi — INDEX_CONFIGS di insert_milvus.py

Jenisindex_paramsCatatan
HNSW (aktif){"M": 16, "efConstruction": 200}M = lebar graph; efConstruction = kualitas build
IVF_FLAT{"nlist": 1024}Aturan kasar nlist ≈ 4·√N (63 rb → ±1.000); Milvus menolak bila nlist > jumlah vektor
FLAT{} (tanpa parameter)Juga terjadi otomatis bila koleksi dibuat tanpa index

b) Saat mencari — parameter search

Jenisparam searchEfek menaikkan nilainya
HNSW (ef 64){"ef": 64}ef 64 → 128 → 256: recall naik, latensi naik
IVF{"nprobe": 32}nprobe naik → makin banyak kluster dicek → recall naik
FLAT{} (kosong)Tidak ada parameter — hasil selalu exact
Kesimpulan README-retrieval §7: “Yang berubah hanya index_params saat membuat koleksi dan params saat search (ef untuk HNSW, nprobe untuk IVF, kosong untuk FLAT) — schema, insert, encoder, dan aturan ‘model index = model query’ tidak tersentuh.” Parameter search bebas diubah tanpa insert ulang; index type terikat di koleksi (ganti = --rebuild-index atau koleksi kedua).

4. Baseline exact — dua jalur yang sudah tersedia

  1. Numpy murni (tanpa Docker/Milvus): emb @ q di eval lokal dan cell 7 Colab — 63 rb × 1024 di CPU masih hitungan milidetik per query. Inilah kebenaran acuan eval resmi.
  2. Milvus tanpa index / index FLAT: pembagian kerja yang sama dilakukan di dalam Milvus.

Bukti dari sesi build: top-5 Milvus HNSW (ef 64 maupun 256) identik skor dan urutan dengan numpy exact untuk query kedaulatan UUD 1945 — ANN-nya sehat.

5. Tiga jebakan yang pernah dialami (README-retrieval §5)

  1. Index dibangun belakangan (asinkron). Beberapa detik setelah insert/flush, HNSW belum siap; query bisa mengembalikan hasil yang salah (kasus nyata: demo pertama mengembalikan chunk berbeda dengan skor lebih rendah; run berikutnya sudah identik dengan exact). Solusi: tunggu indeks selesai / jalankan smoke_milvus.py dulu.
  2. IVF sensitif data kecil. Dengan 63 rb vektor, manfaat IVF belum terasa dan recall lebih rapuh terhadap nprobe; FLAT lebih sederhana.
  3. Jangan campur metrik. Semua koleksi memakai IP + vektor L2-normal. Search dengan metrik L2 pada vektor ternormalisasi memberi peringkat yang terbalik secara skala.

6. Rekomendasi untuk dataset ini (README-retrieval §6)

KebutuhanPilihan
Benchmark / kebenaran acuanNumpy exact (eval lokal & cell 7 Colab) — sudah ada, jangan diubah
Dataset saat ini (63 rb)FLAT atau HNSW sama-sama cepat; HNSW ef 64–128 aman untuk produksi
Nanti jutaan vektor / latensi ketatHNSW dengan ef lebih besar, atau mulai uji IVF_FLAT (nlist ±1.000, nprobe mulai 64)
Aturan lulus ANNrecall top-8 vs exact ≥ 0,99 sebelum percaya angka latensi

Cara mengukur: jalankan eval exact (numpy) dan pencarian Milvus untuk golden set yang sama, lalu bandingkan top_ids per query — persis perbandingan yang dilakukan di sesi build.

7. Ringkasan bab

  • FLAT = exact, 100%, cukup cepat di 63 rb vektor; HNSW = graph ANN, default produksi (ef naikkan recall); IVF = kluster ANN, baru berbunga di jutaan vektor.
  • Ganti jenis pencarian hanya menyentuh index_params & params search — sisanya tak tersentuh.
  • Baseline exact numpy = hakim kebenaran ANN; aturan lulus ≥0,99 recall top-8.
  • Jebakan: indeks asinkron, IVF di data kecil, mencampur metrik.
Istilah baru bab ini: FLAT / brute force, HNSW, IVF / nlist / nprobe, ef, ANN (ulang), latensi.
