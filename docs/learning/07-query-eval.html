Bab 07 · Query & Eval

Dari Pertanyaan Manusia ke Recall@8 — Cara Mengukur “Bagus” secara Jujur

Sisi pakai (query) punya kodetnya sendiri: Qwen3 memakai instruksi tugas + last-token pooling yang berbeda dari sisi dokumen. Dan yang lebih penting: bagus menurut siapa? Proyek ini memakai 12 golden_queries.jsonl (pertanyaan emas dengan jawaban yang diketahui) dan mengukur recall@8 — hasil resminya 0,750. Kita bedah keduanya.

⏱️ ±15 menit baca File: embed_query_qwen.py · eval/eval_retrieval.py · eval/golden_report.json

1. embed_query_qwen.py: sisi pertanyaan

Kenapa file ini terpisah? Dokstringnya menjawab (baris 5–8): pooling Qwen3-Embedding adalah LAST-TOKEN + instruksi tugas pada sisi query — berbeda dari mean-pooling + prefix e5 di Bab 05. eval_retrieval.py membaca meta.json dan memakai encoder ini bila meta.pooling == "last_token". Sumber kebenaran parameter = meta.json — “jangan mengarang model/dimensi di sini”.

pipeline/embed_query_qwen.pybaris 58–89 (inti)
@torch.no_grad()def encode_query(texts: list[str], model: str | None = None, instruction: str | None = None, max_length: int = 512, batch: int = 8) -> np.ndarray: meta = load_meta() model = model or meta.get("model") instruction = instruction or meta.get("query_instruction", "") keep_dim = meta.get("keep_dim") or meta.get("dim") for i in range(0, len(texts), batch): chunk = [f"Instruct: {instruction}\nQuery: {t}" for t in texts[i:i + batch]] enc = tok(chunk, padding=True, truncation=True, max_length=max_length, return_tensors="pt").to(dev) hs = mdl(**enc).last_hidden_state mask = enc["attention_mask"] if (mask[:, -1] == 1).all(): # left padding → posisi terakhir pooled = hs[:, -1] else: seq = mask.sum(dim=1) - 1 pooled = hs[torch.arange(hs.shape[0], device=hs.device), seq] pooled = torch.nn.functional.normalize(pooled.float(), p=2, dim=1) vecs = np.concatenate(out).astype("float32") return vecs[:, :keep_dim] # MRL: pangkas dimensi sesuai meta.json

Tiga hal yang perlu dicermati:

  1. Format query (baris 76): Instruct: {instruksi}\nQuery: {pertanyaan} — instruksi diambil dari meta.json: “Given a user question about Indonesian legislation, retrieve the most relevant legal provisions (norma)…” (dokumen side TIDAK diberi instruksi; ini konvensi resmi Qwen3-Embedding).
  2. Last-token pooling (baris 82–86): padding kiri membuat token terakhir = token asli terakhir untuk semua baris batch; fallback baris 84–86 menjaga bila padding tidak seragam.
  3. MRL keep_dim (baris 89): vektor dipangkas ke dimensi yang tersimpan di meta.json — query dan index otomatis sejajar.

2. 12 golden queries — “ujian” resmi retrieval

File eval/golden_queries.jsonl berisi 12 pertanyaan + ekspektasi jawaban yang bisa dicek komputer (expect_any — cukup satu predikat terpenuhi). Contoh asli:

Arti predikatnya: jawaban yang benar harus dari dokumen yang cocok doc_regex, di pasal yang benar (pasal), dengan kata kunci ada di teks (kw), dan bila disebut, ayat yang benar.

3. Matcher eval: matches() + pas_num()

Matcher menentukan apakah salah satu dari 8 hasil pencarian benar-benar “jawaban emas”. Ada dua perbaikan penting yang lahir dari pemakaian nyata (tertulis di README folder qwen3-06b):

pipeline/eval/eval_retrieval.pybaris 38–68 (inti)
def pas_num(p): if not p: return "" m = re.search(r"(\d+)\s*([a-z])?", str(p), re.I) if not m: return str(p).lower() return "%d%s" % (int(m.group(1)), (m.group(2) or "").lower())⋯def matches(ch, exp): if exp.get("doc_regex"): # official_title UUD bisa berupa stub ("UUD 1945 Perubahan Kedua") — # doc_type_full tetap memuat identitas resmi, jadi cek keduanya. t = (ch.get("official_title") or "").lower() tf = (ch.get("doc_type_full") or "").lower() if not (re.search(exp["doc_regex"], t, re.I) or re.search(exp["doc_regex"], tf, re.I)):
  1. doc_regex dicek ke official_title ATAU doc_type_full (baris 50–54). Kasus nyata: judul UUD berupa stub “UUD” (lihat Bab 03 §4), sehingga regex “undang-undang dasar” gugur meski retrieval-nya benar — versi awal eval menghasilkan recall 0,250 yang salah baca, bukan modelnya yang buruk.
  2. pas_num aman untuk pasal tanpa sufiks (baris 38–44): “7” tetap “7”, “22E” menjadi “22e”, dan tidak crash pada string aneh — normalisasi angka+sufiks huruf.

Ada juga pengulangan longgar di baris 119–121: bila doc+kw cocok tapi pasal/ayat tidak persis, dianggap hit — kompromi agar eval tidak terlalu kaku terhadap variasi penomoran.

4. Inti evaluasi: exact search dengan numpy (baris 110–135)

Satu baris 110 melakukan 12 × 63.231 perbandingan cosine sekaligus — ini exact search (baseline kebenaran, Bab 08). Pemilihan encoder query mengikuti meta.json (baris 94–108): last_token → embed_query_qwen.encode_query; selain itu mean-pool e5 dengan prefix query:. Ambang keputusannya (baris 128 + interpretasi di report): recall ≥ 0,8 bagus; 0,6–0,8 evaluasi ulang model/top-k; < 0,6 jangan lanjut ke agent (kode keluar 2, baris 134–135).

6. Ringkasan bab

  • Encoder query Qwen3: Instruct:/Query: + last-token pooling + keep_dim MRL — parameter dari meta.json.
  • Eval = exact search numpy + matcher predikat (doc_regex ke dua field, pas_num aman) + longgarkan bila doc+kw cocok.
  • Recall@8 resmi: 0,750; 0,90 atas query yang terjawab korpus; 3 MISS punya analisis akar-masalah.
  • Ambang tindakan: ≥0,8 lanjut · 0,6–0,8 evaluasi ulang · <0,6 berhenti & perbaiki.
